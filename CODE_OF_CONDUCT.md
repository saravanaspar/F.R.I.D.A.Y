# Code of Conduct

## Our standard

F.R.I.D.A.Y welcomes contributors, users, reviewers, and researchers who participate in good faith.

Be respectful, technically honest, and constructive. Critique code and ideas rather than people. Assume mistakes are possible, ask for evidence when claims matter, and make room for contributors with different levels of experience.

Examples of constructive participation include:

- giving actionable technical feedback;
- explaining tradeoffs and security concerns clearly;
- crediting prior work;
- keeping issue discussions relevant to the project;
- respecting maintainers' time and review boundaries;
- disclosing security issues privately.

Unacceptable behavior includes:

- harassment, threats, stalking, or targeted abuse;
- discriminatory or demeaning language;
- sexualized comments or unwanted attention;
- publishing another person's private information without permission;
- deliberately flooding issues, pull requests, or discussions;
- knowingly submitting malicious code or deceptive security reports;
- using project spaces primarily for spam, promotion, or unrelated disputes.

## Scope

This policy applies to project-managed spaces such as issues, pull requests, discussions, code review, and other official community channels. It also applies when someone is representing the project in a public community context.

## Enforcement

Maintainers may edit, hide, lock, or remove content and may temporarily or permanently restrict participation when behavior threatens the safety, usefulness, or integrity of the project.

For conduct concerns that should not be public, contact the maintainer through the GitHub profile and request a private channel. For product security vulnerabilities, use `SECURITY.md` instead.

Enforcement decisions should consider context, severity, repeated behavior, and the impact on affected participants and the project.
